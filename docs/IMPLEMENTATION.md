# FrameWeave implementation plan

MiniMax synchronous speech uses fixed `api.minimaxi.com/v1/t2a_v2` with `speech-2.8-turbo` by default. It checks HTTP and business status, decodes completed hex MP3 responses and saves private receipts before validation. Unknown submissions never automatically retry. The write-only audio route holds the key, redirects are not followed, and schema errors omit request inputs. Project casting binds character/narrator voice profiles to speaking shots, with original-line auditions. Snapshots retain the full approved contract and reference bindings. Audio fingerprints invalidate affected audio/renders on voice changes while retaining approved visuals. Offline tests do not establish real MiniMax quality or account availability.

MiniMax error messages retain the HTTP status and an allowlisted response-header support ID, excluding the saved key and raw response text. Balance error 1008 has a specific explanation. These diagnostics do not resolve an earlier uncertain submission; synchronous speech has no documented request-result lookup, and no new synthesis is submitted during diagnostics.

The global voice library preserves activated MiniMax voice IDs, original first-use receipts, private production provenance and checksummed local previews independently of project revisions. Entries are immutable, import is idempotent, and read/preview/backup never calls a provider. Project profiles can bind a library ID; both casting and synthesis verify its original voice ID, and only supported voice parameters reach MiniMax. Missing voices stop without redesign or cloning. Existing activation avoids another first-use voice fee under current provider rules; new dialogue still incurs character charges and voices remain scoped to the provider account. Library retention does not approve audition quality. Offline tests cover preservation, restart, backup, binding tamper rejection and reuse without voice design.

Persistent user policy prohibits any new custom voice design, cloning or activation. Only published/cached provider system voices and already activated library voices may be submitted to MiniMax TTS; unknown IDs stop before submission. Catalogue reads cache only the system category and exclude unactivated custom entries from selections. The MiniMax helper rejects design/clone and other unsupported endpoints before network access. A character profile with `source: "recording"` uses imported audio, blocks TTS, and retains semantic subtitles for cat meows. Selecting existing voices is distinct from approval of newly arranged shot audio. Voice fee exemption does not waive TTS character charges.

## Outcome
Unified local image/video production studio, Chinese UI, six workflow templates, immutable approved Markdown production contract, chapters/episodes/shots/assets, persistent resumable jobs, web-first and explicit paid fallback routing, review and final renders. Source modules stay unmodified as pinned Git submodules. Repo: lhh92xcc/frameweave (public). Runtime uses native processes by default; optional container runtime is OrbStack.

## Boundaries
- `studio/`: application API, SQLite persistence, durable single-worker scheduler, routing, production contract and workflow rules.
- `services/engine_bridge.py`: adapter to the unmodified ai-video-generation chapter parser, media validation, TTS and FFmpeg assembly. `services/renderer.py` isolates canvas/subtitle compatibility.
- `upstream/web2api-web`: isolated web-account and cloud video/image gateway; private state outside submodule.
- `frontend/`: rebuilt Vue/TypeScript studio; shared API client; project, pipeline, assets, jobs, settings.
- `scripts/`: bootstrap, process lifecycle, upstream checks/updates and compatibility verification.

No real external model output or quality claim will be inferred from mocked tests. User supplies model credentials in Settings.

Gemini connections expose the upstream account pool (up to eight saved accounts) in the studio, with individual checks, edits and enable/disable controls. Credentials remain write-only; disabling does not delete them. The gateway prefers enabled accounts in insertion order and can try another account on quota failures or certain timeouts; timeout failover can duplicate a request, so users are warned to inspect provider history. Other current connectors retain their upstream single-credential behavior.

The studio reads and updates the gateway's existing Seedream configuration through a restricted, redacted proxy; the key is stored only by the gateway. The pinned gateway retains its quota fallback, while the FrameWeave gateway adapter additionally allows a studio image job whose saved snapshot permits paid routes to fall back when all enabled Gemini accounts (at least two) have authentication failures. Mixed errors, uncertain attempts, partial images, timeouts and missing credentials do not trigger that fallback. The permission is persisted with the gateway job before enqueueing, without changing idempotency keys or granting it to native gateway requests. Gateway Seedream configuration with paid routes disabled blocks Gemini image requests. A successful fallback records the actual paid model; Seedream failures require provider-side verification. Offline mocks cover the routing and bindings, not real output or charges.

Workspace and gallery cards and the shared media detail identify the recorded successful route and model for each image/video, including the Seedream fallback instead of the attempted Gemini route. Imported and uploaded assets are explicitly distinguished from model-generated output, missing provenance is unknown, and model IDs are labeled as recorded rather than independently verified. Unknown cost is never presented as free.

Project workspaces show live queue states, latest task events, failures, explicit retry and review waits separately from approval counts. Automatic scheduling records safe planning errors and stops on unresolved current-stage tasks rather than silently resubmitting failed batch items. Browser progress fixtures are explicitly offline and do not represent external model output.

Reference and keyframe views support explicitly selected pending items, select-all within the current view, shared notes and individual approve/rework requests. Each request checks that the artifact is still current and pending; already reviewed, stale or archived items are not silently overwritten. Partial failures remain visible with item-specific reasons, and confirmation warns when automatic production may continue after approval.

Explicit retries inspect the gateway job first: active or successful jobs retain their remote ID for polling or result recovery, while a confirmed terminal failure creates a new idempotent local attempt linked to its predecessor. Repeated retries reuse the active or successful successor. Unknown gateway state and potentially completed upstream timeouts require provider-side verification instead of another submission. Offline mocked tests cover these cases and preserve memoized text calls when the snapshot is unchanged.

When the last configured route fails, its remote ID is retained for explicit retry verification rather than being discarded as though another route had been attempted. Safe, code-specific login and account-unavailable explanations are displayed without exposing upstream credential-bearing error text.

User-supplied reference images may be imported while the matching contract and plan are still awaiting approval. They remain pending and cannot be reviewed or used for generation until both are approved; subsequent contract or plan edits invalidate them like any other production artifact.

Reference regeneration snapshots the explicitly selected approved source or the latest user-uploaded reference for that entity and current version. A pending/rejected upload or an upload available only in an older version blocks generation rather than silently falling back to text-only. The original file is materialized and passed through the existing provider reference-image upload path, and its artifact ID is recorded in the immutable job snapshot and output dependencies. Invalid or incomplete gateway reference IDs stop submission, and old queued text-only jobs cannot ignore a newly bound original. The current candidate and source approval are rechecked before submission and before accepting the result; original files and approvals remain intact, while each new result awaits review. Later regenerations continue using the approved uploaded source even after it ceases to be the latest production candidate. Offline mocked tests verify the multipart upload and gateway request, not external image quality.

Curated archives keep current candidates visible alongside selected references. Pending QC is separate from exclusion: default gallery, project counters and exports include both states without changing approvals. Repairs, old tests and historical files remain separate; episode filters show generated, pending, repair and missing counts.

COS is an independent storage adapter in `studio/cloud_storage.py`, with private credentials, explicit resumable selection migration, full-download SHA-256 verification and cloud preview redirects. Production dependencies and ZIP exports can temporarily materialize remote-only files. Uploads retain local copies and original approvals; backup failures never resubmit generation. Automatic backup is opt-in and applies to all projects.

Image generation snapshots a separate vision route and bounded attempt count. Each reference or keyframe candidate is sent with its approved dependency images, full production contract and bindings to the configured multimodal reviewer; the gateway chat reference upload and compatible cloud image-data messages carry the actual files. Seven structured checks must be present; failures or uncertainty produce a bounded corrective retry, and malformed/unavailable reviews or exhausted attempts block instead of creating a reviewable artifact. Aspect mismatch also fails the initial check. Prompts, candidates, findings and route records remain in the job; only a passing candidate becomes pending human review. Checkpoints preserve completed image calls and pending QC candidates across worker restarts or explicit QC retries; unknown provider submissions still require verification. These are model assessments, not proof of identity or temporal video consistency. Offline mocked tests do not establish actual model quality.

Per-shot reference bindings add explicitly approved, current-version images for the shot's bound assets and optionally an earlier approved keyframe to the default latest approved references. The ordered IDs are snapshotted and revalidated, and changing a binding or upstream review invalidates dependent keyframes and videos. Each additional image can represent a front/side view, costume, location angle or prop detail; users upload and approve them individually. A plan edit clears these bindings. Provider reference limits are enforced without dropping images, including the candidate image needed for vision QC.

Reference uploads carry a user-chosen role appropriate to their asset type: character front, side, full body, costume or accessory; location wide, reverse or spatial; prop/product detail or held state. Existing unlabelled references remain general. Reclassification requires reapproval and changes the review version; dependent candidates remain invalid even if the reference is subsequently approved again. These are user-provided categories, not automatic detection or a guarantee that a library is complete; users choose relevant images for each shot. Approval of a reference's source is checked transitively, and revoked approvals invalidate downstream current candidates. Per-image CNY budgets and user-supplied per-route maximum estimates are snapshotted; each potentially paid image or vision call, including Gemini with paid fallback enabled, reserves its configured estimate before submission. A retry of the same call reuses the reservation; missing estimates or an exceeded budget block. These controls cannot guarantee provider pricing or actual charges. Explicit new jobs have separate budgets.
